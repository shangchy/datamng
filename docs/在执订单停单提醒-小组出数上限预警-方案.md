# 在执订单「小组出数上限」预警 — 实现方案

> 状态：方案已确认，暂不开发。
> 记录日期：2026-10-26

---

## 一、需求

给每个「小组」设定一个出货上限。当该小组在执订单的累计出数按当前日均速率即将撞到上限时，给小组内的在执订单生成预警（在预警中心可见、可处理）。

## 二、数据模型：新增「小组出数配置」表

表名：`group_limit`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键 |
| customer_id | INTEGER | 一级代理（关联 customer.id） |
| group_name | VARCHAR | 小组名 |
| qty_limit | INTEGER | 出货上限（条） |
| created_at / updated_at | TIMESTAMP | 审计 |
| created_by / updated_by | VARCHAR | 审计 |

- 唯一约束：`UNIQUE(customer_id, group_name)`
- 新增到 `models.py`；由 `Base.metadata.create_all` 自动建表，无需额外 ALTER 迁移。

## 三、出数统计口径

对一个配置了上限的小组 `(customer_id, group_name)`：

1. 找出该组**在执订单**：`Order(status='在执', customer_id=?, group_name=?)`，取其 `task_id` 集合。
2. `已出数 = count(DailyData)`，其中 `DailyData.task_id ∈ 在执订单.task_id`。
3. `首次出数日期 = min(DailyData.biz_date)`（同小组订单首次有出数的日期）。
4. `已出货天数 = 当前系统日期 − 首次出数日期`（天数差；为 0 时按 1 处理，避免除零）。
5. `日均出数 = 已出数 / 已出货天数`。

> 说明：`已出货天数` 按「当前系统日期 − 首次出数日期」计算；无出数记录（首次出数日期为空）时不触发预警。

## 四、预警触发规则

对每个小组，若同时满足：

```
已出数 < 出货上限
且 已出数 + 日均出数 >= 出货上限
```

则触发预警（即：按当前日均速率，再出一天就会撞到上限）。

触发后，给该小组内**每个在执订单**生成一条 `Alert`：

- `type = "出数预警"`、`level = "提醒"`、`status = "未处理"`；
- `order_id / task_name / order_no` 关联具体订单；
- `content` 示例：`小组「xx」累计出数 9000/10000，日均 1000，即将达到出货上限，请确认是否停单`；
- 未处理则不重复创建（去重）。
